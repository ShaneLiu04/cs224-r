## 核心概念

### 1. 算法总结地图

```text
                   需要数据从哪来？
        ┌── 专家演示 ──► 模仿学习（BC / DAgger / diffusion policy / flow）
        │
数据 ───┼── 与环境交互 ─┬─ on-policy：REINFORCE → PPO/A2C（稳定、低样本效率）
        │              ├─ off-policy：SAC/DDPG/TD3（高样本效率）
        │              └─ value-based：Q-learning/DQN（离散动作、可重放）
        │
        └── 固定数据集 ──► 离线 RL（AWR/AWAC、IQL、CQL、决策 Transformer）
                             │
模型 ◄──────────────────────┘  模型无关 vs 模型类（MBPO、PETS、MuZero、Dreamer）
```

每一类都可用一个「配方」描述：**策略参数化 + 价值/优势估计 + 数据策略 + 优化器 + 正则**。

### 2. 算法的组成部件

| 部件 | 可选设计 | 影响 |
| --- | --- | --- |
| 策略 | 高斯、tanh 高斯、diffusion、flow、自回归 | 表达多模态、似然可算性 |
| 价值/优势 | MC、TD、GAE、组内相对（GRPO/RLOO） | 偏差-方差、是否需要 critic |
| 数据 | on-policy、replay、离线、混合 | 样本效率、稳定性 |
| 优化 | 似然比、重参数化、QP、条件 BC | 梯度方差、实现复杂度 |
| 正则 | KL、熵、clip、保守惩罚、BC 正则 | 探索与安全 |

很多「新算法」只是替换了表中一到两格。

### 3. 开放问题（slides 的清单）

1. **无奖励/难验证领域**：奖励不存在或极度延迟（科研、写作、长期健康）；
2. **长时域与信用分配**：数小时到数天任务的稳定学习；
3. **真实世界约束**：安全、可复位、昂贵采样；
4. **评估**：离线评估、OOD 泛化、reward hacking 检测；
5. **多智能体与社会性**：博弈、合作、机制设计；
6. **推理与算力的经济学**：test-time compute、token 预算、成本感知；
7. **模型类 RL 与生成模型的融合**：世界模型、视频模型、LLM 做规划。

### 4. 如何做 RL 研究

讲者与课程的建议可以归纳为：

1. **读论文的三遍法**：标题/摘要 → 图表与结论 → 方法细节与失败案例；
2. **复现一个可信 baseline**：跑通环境与随机种子，记录方差；
3. **找缺口**：读 related work 的「future work」、复现中的不一致、跨领域迁移的空白；
4. **提出可证伪的假设**：写成「如果 X 假设成立，那么 Y 指标会 Z 变化」；
5. **单变量实验**：控制变量、足够 seeds（≥3–5）、报告均值与方差；
6. **严谨评测**：训练奖励 ≠ 真实目标；离线评估要用 held-out；避免只调一个任务；
7. **失败分析**：保存失败 rollout，比成功案例更有信息量；
8. **写作**：先画图与表格，再写故事；明确 claim、证据与局限。

### 5. 研究品味

- 选择「重要且可做」的问题：影响面 × 当前可行性；
- 小步快跑：先做玩具环境验证机制，再上真实规模；
- 拥抱负结果：记录下来，避免重复踩坑；
- 区分「工程 trick」与「科学贡献」，论文要能解释 why。

### 6. Bitter Lesson 的启示

Sutton 的《The Bitter Lesson》：利用算力与学习的通用方法最终胜过手工知识。
对 RL 的含义：与其设计精巧的领域特征，不如投资可扩展的学习算法、环境与评测。
但「可扩展」不等于「无脑堆算力」：样本效率、稳定性与评估仍然决定成败。

## 关键推导：如何把一个想法变成可发表的 claim

```text
Claim:   在设定 X 下，方法 M 比 baseline B 在指标 Y 上提升 Z。
证据：   控制变量的对照实验 + 多 seed + 显著性与失败案例。
机制：   消融实验证明关键组件 C 的作用（去掉 C 则增益消失）。
边界：   在设定 X' 下失效，给出原因（如探索不足/模型误差）。
```

这套模板也适用于期末项目与面试中的「你做过的研究」叙事。

## 易错点与反例

- **只跑一个 seed**：RL 方差极大，结论不可信；
- **调参调到测试集**：报告的数据泄漏；
- **用训练奖励证明方法好**：需要独立评估与真实目标；
- **把失败归因于超参**：先诊断（梯度、数据、探索、实现），再调参；
- **重复造轮子**：先确认环境/baseline 的官方实现与已知坑。

## 实验或练习

1. 选一篇课程论文（如 IQL 或 DPO），列出它的 claim/证据/消融/局限四要素；
2. 为期末项目写一页 proposal：问题、baseline、假设、实验、评测、风险；
3. 建立 `experiments/catalog/` 中的一张实验卡，记录一次完整实验（含失败）。

## 高频问题

- 问：RL 研究常见的有效性威胁？答：方差、数据泄漏、奖励代理、单一任务过拟合。
- 问：怎么选研究方向？答：重要问题 × 可行方法 × 可测指标。
- 问：为什么论文需要消融？答：证明增益来自声称的机制而非调参/容量。
- 问：Bitter Lesson 与领域知识矛盾吗？答：不矛盾；领域知识用于设计可扩展的学习设定。
- 问：课程结束后怎么继续？答：复现一个经典算法 → 选一个开放问题 → 跑通端到端实验。

这门课从 MDP 一路走到 VLA 与推理模型，主线始终是：**在什么数据/模型/奖励假设下，
